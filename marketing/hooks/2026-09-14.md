## 이번 사이클의 문제 (있는 그대로)

이 세션의 네트워크 정책이 `WebFetch`(임의 URL 직접 열람)를 전면 차단합니다 —
Reddit, Apple App Store, 심지어 Wikipedia까지 도메인을 가리지 않고
`EGRESS_BLOCKED`로 막혔습니다 (직접 테스트 확인, 2026-09-14). 남은 도구는
`WebSearch`뿐인데, 이건 실제 페이지 원문이 아니라 **AI가 요약·재서술한 결과**를
줍니다. 요약 중간에 큰따옴표로 감싼 문장이 나오기도 하지만, 그 문장이 정말
원문 그대로인지, 어느 URL에서 나온 것인지를 제가 직접 페이지를 열어 대조할
방법이 없었습니다 — 후보 URL이 여러 개 나열된 경우 어느 것이 그 인용의
출처인지조차 특정할 수 없는 경우가 대부분이었습니다.

`marketing/README.md`와 이 지시가 요구하는 기준은 "verbatim 인용 + 출처 URL"
입니다. 검증할 수 없는 문장을 인용부호로 감싸 "훅"이라고 넘기는 건 지어내는
것과 실질적으로 같다고 판단해 — 지시받은 대로 **적더라도 지어내지 않는 쪽**을
택했습니다.

(참고: 같은 세션에서 PeriodVol 저장소를 열어보니 `marketing/cycle-2026-08-08/`에
이미 이런 스카우트→훅 사이클을 사람이 직접 돌린 기록이 있습니다 — 그 사이클은
브라우징이 되는 환경에서 진행된 것으로 보입니다. SaveBoard에도 같은 사람 주도
리서치가 필요해 보입니다.)

## 검증 없이는 못 쓰지만, 다음 리서처에게 남기는 단서

인용은 아니지만 여러 검색 요약에서 반복적으로 등장해 **주제 자체는 실재한다는
확신**을 준 소재들 — 사람이 직접 원문을 열어 확인하면 바로 훅으로 쓸 수 있을
가능성이 높습니다:

1. **Pocket 종료는 확실한 사실입니다** (2025-07-08 서비스 종료, 2025-11-12
   API 완전 중단 — TechCrunch·TechRadar·Mozilla 공식 지원 문서가 일치). "이제
   뭘 써야 하지" 류의 이주 글이 다수 존재한다는 신호는 있으나, 특정 개인의
   문장을 저는 확인하지 못했습니다.
2. **북마크 방치 패턴**은 여러 출처에서 "저장은 하는데 다시 안 본다"는 표현이
   반복됐습니다 (예: dev.to 계열 글, 익명 블로그). 정확한 문장·출처 매칭 실패.
3. **Notion을 북마크 도구로 쓰다가 포기하는 글**들이 존재합니다
   (`contextbolt.com/blog/notion-bookmarks-alternative` 등) — 다만 이 도메인은
   자체 북마크 제품을 파는 곳의 콘텐츠 마케팅 블로그로 보여, 진짜 사용자 불만이
   아니라 판매 목적 글일 가능성이 있어 애초에 훅 후보로도 부적절합니다.
4. **단톡방/맘카페 소재**는 이번 검색으로는 전혀 건지지 못했습니다. 82cook,
   맘카페(다음), 네이버 카페 등은 검색엔진에 거의 안 잡히거나 로그인 벽이 있어
   `WebSearch`로는 원문 근처에도 못 갔습니다 — 사람이 직접 로그인해서 봐야
   하는 영역으로 보입니다.
