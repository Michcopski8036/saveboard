# 공유 저장 실기기 확인 목록 (2026-09-05)

**왜 하는가:** 경쟁 도구 리뷰의 불만이 "공유 시트가 없다"가 아니라 **"인스타·트위터에서
조용히 실패한다 / 저장해도 뭔지 알아볼 수 없다"** 였다(2026-09-05 실사, 앱스토어 리뷰 원문).
우리가 거기서 안 깨진다면 그게 실제 무기다. **다만 아직 아무도 확인하지 않았다** — 코드만
읽었고 실기기 기록이 없다. 확인 전에는 이걸 마케팅 문구로 쓰지 않는다.

## 코드에서 미리 아는 것 (실측 아님, 예상 실패 지점)
`src/app/utils/metadataFetcher.ts`

| 공유 출처 | 카드 이미지 | 근거 |
|---|---|---|
| YouTube / Shorts | **실제 썸네일** | `img.youtube.com/vi/<id>/maxresdefault.jpg` |
| Vimeo | 실제 썸네일 | `vumbnail.com` |
| **Instagram · TikTok · X · Facebook · LinkedIn** | **브랜드색 플레이스홀더** (내용 안 보임) | `getDomainImage()`가 `placeholder:*` 반환 |
| 그 밖의 웹 | OG 태그 시도 | `fetchMetadata` |

⚠️ 인스타·틱톡은 로그인 없이 미리보기를 안 주므로 **이 카테고리 전체가 못 하는 일**이다
(mymind도 같은 리뷰를 받았다). 우리 결함이 아니라 제약이다. 다만 **스토어 설명이 인스타를
첫 예시로 들고 있어**, 사용자가 그 말을 믿고 첫 저장을 인스타로 하면 우리 강점(비주얼 카드)이
안 보이는 경우를 첫인상으로 만난다.

## 확인할 것 — 앱마다 "공유 → SaveBoard → Add"

각 항목에 대해 ① 공유 시트에 SaveBoard가 **뜨는가** ② 저장이 **끝나는가**
③ 카드에 **무엇이 보이는가** ④ 저장 뒤 **원래 앱으로 돌아오는가**(안드로이드, 09-05 추가된 동작)

- [ ] **YouTube** 영상 · [ ] YouTube **Shorts**
- [ ] **Instagram** 게시물 · [ ] Instagram **릴**  ← 경쟁사 리뷰의 실패 지점
- [ ] **X(트위터)** 트윗  ← 경쟁사 리뷰의 실패 지점
- [ ] **카카오톡** 대화 속 링크  ← 한국 사용자의 주 경로. 아무도 확인한 적 없음
- [ ] **크롬/사파리** 웹페이지
- [ ] **틱톡** 영상
- [ ] **스크린샷**(사진 앱에서 공유) — iOS 공유확장은 이미지를 받게 돼 있다
- [ ] 로그아웃 상태에서 공유했을 때 무엇이 보이는가  ← Raindrop 리뷰의 불만("로그인을 계속 요구")

**기록할 것:** 실패하면 **어느 단계에서** 실패했는지(공유 시트에 안 뜸 / 앱은 열리는데 URL이
비어 있음 / 저장은 되는데 카드가 이상함). 스크린샷 한 장이면 충분하다.

## 이 결과로 갈리는 것
- 전부 통과 → **"인스타·유튜브·카톡에서 깨지지 않고 저장된다"**를 근거로 쓸 수 있다.
  경쟁사가 리뷰로 욕먹는 바로 그 지점이다.
- 인스타·틱톡 카드가 초라하다 → **스토어 설명의 첫 예시를 YouTube로 바꾼다.** 그게 실제로
  가장 잘 보이는 경우다.
- 카톡이 실패 → 한국 사용자에게 치명적이므로 마케팅보다 수정이 먼저다.
