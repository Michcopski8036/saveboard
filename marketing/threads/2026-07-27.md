## Post 1 — the Stripe webhook that 500'd for a week

Every Stripe `subscription.updated` webhook to SaveBoard failed for almost a
week — 14 out of 14 deliveries between July 16 and July 20 came back 500.

The cause: Stripe moved `current_period_end` off the Subscription object onto
line items in an API version newer than the one my code was written against.
My handler read `undefined`, tried `new Date(NaN).toISOString()`, and threw
`RangeError: Invalid time value`.

There was a second bug hiding under the first: supabase-js returns errors
instead of throwing them, so a failed database write on the same path was
quietly swallowed and returned 200 anyway — a real failure looked like
success. Fixed both: read the date off the line item now, and let DB errors
throw so Stripe actually retries.

The outage also surfaced something worse — a subscriber whose payment had
failed had no way to reach the billing portal to fix their card, because the
button was gated on `status === 'active'`. Fixed that path too.

**Source:** CHANGELOG.md "Web-only — Stripe billing fixes, 2026-07-20";
commits `7cfc1001` (webhook 500 fix), `88e11593`/`874f2858` (payment-failure
banner), `737cda09` (portal access for lapsed subs), `f350f2d6` (plain-language
status), `edec37c6` (brand palette).

## Post 2 — two white bands and a tab bar that was too tall

Shipped an iOS build with a white band running above the header and another
above the tab bar. Cause: `capacitor.config.json` had `ios.contentInset:
"always"`, so WKWebView was applying its own safe-area insets on top of the
CSS I'd already written for `env(safe-area-inset-top/bottom)`. Inside an
inset webview those `env()` values resolve to 0, so my spacers collapsed to
nothing and the strip the webview reserved for itself just rendered as bare
background. One-line fix: `contentInset: "never"`.

Same release, second bug: my bottom tab bar was `h-16` (64pt) against a
native `UITabBar`'s ~49pt. With the safe-area spacer that came to a measured
98.3pt, against iOS's own 82.3pt — I checked by sampling a simulator
screenshot at the edge where no button content interferes. Dropped it to
`h-12`; now measures 82.3pt, matching stock.

**Source:** CHANGELOG.md "iOS 1.0.8 (build 20)... — prepared 2026-07-22";
commits `5d9d1a4` (white bands / contentInset), `5ee03d1` (tab bar height).

## Post 3 — ran a risk review, fixed four real ones

Ran a security review on SaveBoard this week and fixed four issues before
they became incidents:

- The admin auth check on a few internal endpoints decoded a JWT's payload
  and trusted whatever email was in it — without ever verifying the token
  was actually signed by Supabase. Switched it to Supabase's own
  `auth.getUser(token)` call, which checks the signature properly.
- Two billing endpoints trusted a user ID sent in the request body with no
  auth check tying it to the caller. Now both require a valid session token
  and confirm it matches the account being billed.
- Page descriptions scraped for link previews were rendered as HTML with
  only a shallow check — added proper sanitization (DOMPurify) at every
  render site, and strip tags at the point the content is first scraped.
- The link-preview fetcher had no restriction on what it would fetch
  server-side. Added a guard that only allows public internet addresses,
  re-checked on every redirect hop.

All four shipped in one pass, none required a data migration, no user
action needed.

**Source:** commit `a519320` ("Security: verify admin JWTs, fix payment
IDOR, sanitize HTML, guard SSRF"), 2026-07-23.
