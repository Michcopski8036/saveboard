# Shortform batch — 2026-07-20 (second pass)

Source: `marketing/hooks/2026-07-20.md` — a thin week, 7 hooks (2 counted as one Korean
source, 5 English), several unusable as direct testimonials. Read that file's honesty
notes before touching this one.

**What this batch does NOT do, on purpose:**
- Does not script a Korean "parent loses the link in the group chat" scene, because the
  hooks file explicitly could not source a real quote for that scenario this week. Every
  Korean script below traces to hook #1 (Threads, general saver) instead.
- Does not claim SaveBoard fixes chat/notification delivery (hooks #2–#4 are TeamSnap
  complaints about messaging reliability, not about saving links).
- Does not claim a browser-extension save flow (hook #1's poster mentions a "모바일
  확장프로그램"; SaveBoard's actual save flow is share-sheet based on both iOS and
  Android — confirmed in `src/app/App.tsx` via `send-intent`, and the iOS
  `ShareExtension` target). No script below shows or claims an extension.
- Does not present hooks #5, #6, #7 as real user testimonials — they're competitor
  blog marketing copy (ContextBolt, Dewey). Where used, they're framed as an
  observation/premise line, never as "a user said" or "someone online said."

**Verified against the repo before writing shots** (so nothing below asks the founder
to film a feature that doesn't exist):
- Save flow: share a link into SaveBoard from any app's share sheet → Add modal opens
  pre-filled with the URL (`App.tsx`, `SendIntent.checkSendIntentReceived`). No manual
  form — title/description/image are auto-fetched (`utils/metadataFetcher.ts`), and tags
  are auto-suggested from the URL/title/description (`deriveAiTags`, confirmed also in
  `HelpPage.tsx` FAQ: "SaveBoard analyses the link's URL, title, and description to
  suggest relevant tags").
- Search: the search bar filters on **title, description, and URL** (`App.tsx` line
  ~506–512) — not on saved notes. Scripts below only claim what the code does (typing a
  keyword that's in the page title/description turns it up), not a notes-search claim.
- Boards: sidebar "+" next to BOARDS creates a new board (`boardName`/`createBoard`
  strings; `CategoryPopup`); links can be moved to a board.
- Sharing: `BoardShareModal` — a "Public link" tab generates a link that opens the
  board with no account needed to view (`shared_boards` RPCs), separate from an
  "Invite people" tab for collaborators.
- Korean UI strings used verbatim below: 링크 검색 (search links), 보드 (board), 보드
  만들기 (create board), 즐겨찾기 (favorites), 공유 (share).

**Totals: 7 scripts — 5 English, 2 Korean.** Ratio note: this lands at roughly 3
demo : 2 relatable for English (close to, not exactly, the usual 2:1 — five is an odd
number and the strongest premise-driven material this week skewed relatable). Korean is

## KO-1 — 스크린 데모 (15초)
**출처:** Hook #1 (Threads, 미확인 앱에 대한 후기). "확장프로그램" 언급은 사용하지 않음 —
SaveBoard 저장 방식은 공유 시트 기반(iOS 공유 확장 / Android send-intent, 저장소
확인됨)이며, 브라우저 확장 저장 방식을 주장하지 않음. 후기가 실제로 SaveBoard를
말하는지 불확실하므로, 이 후기를 "SaveBoard 사용자의 후기"로 인용하지 않고 저장 후
썸네일이 있어 나중에 찾기 쉽다는 부분(=실제 SaveBoard 동작과 일치)만 대본의 소재로
사용함.

**촬영 필요:** 폰 화면 녹화. 카톡(또는 유사 메신저) 대화방에서 링크 공유 → SaveBoard로
공유 → 자동으로 제목/이미지/설명 채워지는 Add 모달 → 보드 선택 후 저장 → 검색창에
키워드 입력해서 바로 찾아지는 장면까지.

```
HOOK (0-2초)
화면: 링크가 잔뜩 쌓인 SaveBoard 보드 화면 위에 자막
"북마크 앱 다 써봤는데, 결국 여기 정착했어요"

장면
1. (2-5초) 화면 녹화: 단톡방에서 링크 길게 눌러 공유하기 → 공유 시트에서
   SaveBoard 선택. 자막: "저장은 다 비슷하죠"
2. (5-9초) Add 모달 자동 완성 — 제목, 썸네일, 설명이 이미 채워져 있음.
   자막: "한 줄짜리 텍스트가 아니라, 썸네일까지"
3. (9-12초) 보드 선택 후 저장. 자막: "북마크 마구마구 쌓여도"
4. (12-14초) 링크 검색창에 키워드 몇 글자만 입력 → 바로 결과 뜸.
   자막: "찾을 땐 몇 글자면 충분해요"

CTA (14-15초)
자막: "결국 정착하게 되는 이유, 저장이 아니라 찾기예요."
```
